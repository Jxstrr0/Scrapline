# Scrapline: build plan

A combat-robot builder and career game by Longlight Interactive. Design a fighting robot under a weight limit, prove it on the bench, drive it against an opponent whose build is just as considered, patch it in the pit, read the post-mortem, and build better. From a plywood box in a rented corner of a Haldis machine shop to the televised Scrapline Open heavyweight championship. Phone-first, free, hosted on GitHub Pages, listed on Kelbo.Website.

Hand this file to a Claude Code session, e.g.:

> Read `CLAUDE.md` (if it exists yet), then `docs/SCRAPLINE-PLAN.md`. Do PR 0 only. Stop when it's merged and give me the phone test.

Commit this file as `docs/SCRAPLINE-PLAN.md` in the `Scrapline` repo so every session can find it. Tick off PRs in the checklist at the bottom. Section 1 holds every confirmed decision. Every design question has been answered; section 17 says how to handle new ones.

## 0. Ground rules

- **Stack is PEW's stack, lifted directly.** Reference repo: `github.com/Jxstrr0/350Chev` (PEW), the only one. Read its `CLAUDE.md`. Copy `build.js` and the shape of `check-savecode.js`. Plain HTML, CSS and classic (non-module) JavaScript in `<script>` blocks. No package.json, no npm, no bundler, no CI. three.js r128 from CDN (same on-demand `PEW_LIBS` pattern). Google Fonts only.
- **Edit `src/` only.** `index.html` and `sw.js` are generated by `node build.js` from `src/manifest.txt`. Run `node build.js`, `node build.js --check`, `node check-savecode.js` before every commit. Commit `src/`, `index.html`, `sw.js` together.
- One `claude/...` branch + PR per section. Keep each PR readable on a phone. Bump the **third** VERSION number (`src/app/state.js`) per PR; fourth for hotfixes. Merge commit title `x.y.z.w: summary`.
- **Three graphics tiers** (`lite`, `full`, `ultra`, `src/app/perf.js`). Lite is the phone default and must keep working after every change.
- **Three namespaces:** `SCRAP_SIM` (parts maths, bench tests, the fight simulation, AI drivers; never touches DOM or three.js; runs in plain node), `SCRAP_VIS` (three.js; draws what the sim says), app glue in `src/app/`. **The fight is simulated by `SCRAP_SIM` at a fixed timestep; the 3D view only renders it.** This is what makes fights testable and balanceable in node.
- **Determinism is a hard rule.** `SCRAP_SIM` uses one seeded PRNG (mulberry32 or similar) passed in as an argument. `Math.random`, `Date.now` and `performance.now` are banned inside `src/sim/`; `tools/sim-test.js` fails if it finds them there.
- **Units:** parts tables are in grams and millimetres because that's how builders think. `evalBuild` is the one conversion point; everything it returns and everything the fight sim uses is in kg, m, s, J, W.
- **Tuning numbers live in tables, not inline.** Every table is named in this plan.
- localStorage wrapped in try/catch. Keys: `scr-save`, `scr-slot1` to `scr-slot3`. New *fields* inside `scr-save` are fine (bump its `v` and migrate). A new localStorage *key* must be added to `buMake`/`buWrite` in `savecode.js`; stop and ask before adding one.
- Save codes: `SCR1:` + the keys as JSON, LZW-squeezed, base64url, + 6-char checksum. Copy PEW's save safety too (backup file, storage-persist request, the quiet "no backup in 14 days" bar, `lastBackup`).
- Respect `prefers-reduced-motion` and `prefers-reduced-transparency`. Light theme gets every UI change; the 3D view stays dark in both themes.
- Comments in plain English at the top of each file say what it holds.
- Real design decisions get asked, not guessed. End each PR with a plain-language "what changed / how to test on a phone" summary.
- Deploy: GitHub Pages from `main` (`.nojekyll`). Merging into `main` is the deploy.
- **Assets:** CC0 or CC-BY only (from 0.1.54 also art generated with Higgsfield, credited as generated: section 1), credited in `models/CREDITS.md`, `sounds/CREDITS.md`, `textures/CREDITS.md` (name, author, licence, URL). Kelbo's own Blender work is noted as original. No asset with NC or ND terms.
- The site and the game use the name Kelbo only. Credit line: "© year Kelbo / Longlight Interactive".

## 1. Decisions

| Topic | Decision |
|---|---|
| Title / repo | **Scrapline** / `Jxstrr0/Scrapline`. The game shares its name with its league, the Scrapline. Live at https://jxstrr0.github.io/Scrapline/. (Earlier working title Servo, dropped.) |
| References | **PEW (`Jxstrr0/350Chev`) is the only code and design reference.** The Escapement repo supplied the setting's names only (Velmark, the Haldis); nothing else from it is used, in code, docs or design |
| Prefixes | Namespaces `SCRAP_SIM`, `SCRAP_VIS`, `SCRAP_SOUND`; localStorage keys and caches start `scr-`; save codes start `SCR1:`; backup files `scrapline-backup-YYYY-MM-DD.txt` |
| World | **Velmark**, an invented alpine country. The player starts in **the Haldis**, its northern watchmaking valley. Money is **euros** (`€4,850`, whole amounts), formatted by `fmt$`. Place names live in one `WORLD` table in `state.js` |
| Venues | Club meets at the **Haldis Gemeindehalle**; regional tournaments in **Stahlbrück** (steel-mill city), **Eisenau** (river port) and **Grauwald** (forest rail town); the Scrapline Open's home arena is **the Eisenhalle** |
| League | **The Scrapline** is Velmark's robot-combat circuit; **the Scrapline Open** is its televised heavyweight league. No real league or TV brand is named |
| Weight classes | Ant 150 g · Beetle 1.5 kg · Hobby 5.5 kg · Feather 14 kg · Heavy 110 kg |
| Fight control | **Two schemes, picked in Settings:** direct (left-thumb virtual stick, right-thumb weapon button) and tactical (tap where to go, tap to attack). Both produce the same per-step sim inputs (section 7a), so one sim serves both. Keyboard and gamepad on desktop |
| Assists | Auto-straighten, turn damping and weapon auto-spin **shrink as driver skill grows** (`ASSISTS` table keyed by skill) |
| Fight length | 90 s rounds. Best of one early in the career, best of three in finals |
| Lethality | A single big hit **can** end a fight, but rarely; tuned by the balance harness (section 8d) |
| Modes | 1v1, **rumbles** (3–4 bot free-for-all), **tag team** (2v2), and **minibots**. The sim is N-body from PR 4 |
| Parts economy | **Pay on fit, no refund** (Kelbo, PR 2; PEW's swap rule, "no refund on cut metal"). No parts inventory. Build-tab edits are a draft; tapping **Fit** shows the bill for every part that differs from the fitted bot, at full price, then charges it. Parts taken off are gone. A new weapon pays for its material too. Moving parts on the grid is free. Nothing is charged before the career exists (PR 7) |
| Bench | **Tests the fitted bot only** (Kelbo, PR 3): the draft has to be fitted first, and the Bench says when the draft has unfitted changes. **The rig is safe:** nothing the impact or drop test breaks is kept; the bench costs workshop hours (from PR 7), never repairs |
| Balance set | **Sloppy budget is left out of the 35–65% archetype target** (Kelbo, PR 4b): it is the "how not to build" example and may lose. Glass cannon counts. The harness still prints Sloppy's numbers |
| Balance arena | **Each class balances in its own usual arena** (`CLASSES[cls].arenaId`, with its hazards; Kelbo, PR 4b). The plain test box stays for the bench and debugging |
| Hold limit | A lifter or crusher lets go after **10 s** (`FIGHT.holdMaxS`, PR 4a review), as most real leagues rule |
| Pin limit | A pin (under a wedge, or against a wall) is broken after the same **10 s**: the pinner backs off for 1.2 s (`FIGHT.releaseS`; PR 4b default, after real league rules) |
| Balance slack | `tools/fight-test.js` fails a test build more than **5 points** outside 35–65% and lists one inside that, since 12 seeds carry 3–4 points of noise (PR 4b default; tighten it with more seeds if wanted) |
| Lethality | Single-hit knockouts come from a **shock** rule: a hit at 60%+ of the disc's full energy has a small chance per class (failsafe electronics halve it) to shake the electronics loose. Heavyweight hits count 1.2x (`FIGHT.shock`, `FIGHT.lethal`; PR 4b default) |
| Fight screen | **The arena fills the screen while a fight is on** (PR 5 default): the panel and tab bar hide, an overlay carries the clock, a strip per bot and the controls; Pause offers Stop, and the bell offers Rematch or Results |
| Spinner button | A spinner's weapon button **switches the disc on and off; it is on at the bell**. With assists on (the rookie's) it only spins up when an enemy is near (PR 5 default) |
| Rumble line-up | Sparring's rumble is you, the opponent you picked and **two more from the class's named opponents and test builds, picked by the seed** (PR 5 default) |
| Pit kits when sparring | **Free to pick when sparring**; the price (x the class's `prizeScale`) applies from the career on (Kelbo, PR 6) |
| Best of three when sparring | Sparring gets a **Best of three** format, so the pit window can be tried before the career (PR 6 default) |
| Replay scrubbing | **A jump re-runs the sim from the start** to that moment instead of keyframes (a round is a few milliseconds of sim), so **every tier scrubs**, Lite included (PR 6 default) |
| Career start | **A fresh start** (Kelbo, PR 7): €1,500, hand tools, nothing fitted; bots fitted while sparring are cleared, saved designs stay as blueprints |
| Event fights | **You drive it, or Quick sim** (Kelbo, PR 7): before each fight; a quick sim has the AI drive your bot at your driver skill and your crew does the pit work, for less driver xp |
| Sparring in the career | **Stays free practice** (Kelbo, PR 7): fresh bots, no money, hours, damage or xp |
| Garage calendar | **About ten event days a season** (Kelbo, PR 7): six club meets (four-bot round robins), two one-day tournaments (eight-bot brackets), a rumble night and the club championship |
| Hired driver | **Drives your quick sims** (Kelbo, PR 8) at their fixed skill; "Drive it" is still you |
| Minibots | **A real little bot** (Kelbo, PR 8): an AI wedge one class down on your team that starts behind you, pushes and distracts; it doesn't count for knockouts, the judges or placings, and goes out with its parent |
| Disc profile | **Teeth and rim** (Kelbo, PR 8): one to three teeth (bite against recoil) and a light, medium or heavy rim (stored energy against spin-up), plus a name; one profile per spinner |
| Kit line | **Legacy act, win rate** (Kelbo, PR 8): publish one design; each season it fights the class's test builds in the sim, income = base x prize scale x win rate x rep |
| Team, sponsors, rules (defaults, PR 8) | Salaries are paid weekly at Close week. A sponsor pays at signing (less the weeks gone, at least a quarter) and again at the season end if the target was hit, else drops you; two at most, one per paint slot. Rule changes add up season on season and are announced a season ahead. Custom work (the custom chassis, your own disc) needs a fabricator to fit. An engineer works out the impact and drop lines of the stress report on paper, without the bench |
| Tutorial | **Coached, on a loaner** (Kelbo, PR 9): PEW's First Fire pattern. It runs on a borrowed beetle, so your bots, money and designs are as they were afterwards. Offered after the intro, can be skipped, and can be replayed from Settings |
| Bot card | **3D shot plus stats** (Kelbo, PR 9): a render of the fitted bot from the workshop camera, with its name, class, weight against the limit, weapon, top speed, weapon energy and record. A phone without 3D gets the top-down sketch instead. Shared through PEW's `phoSave` |
| Trophies | **Event wins and titles** (Kelbo, PR 9): a card for every event you win, and a gold one for an act championship or a move up an act. They are kept in the save and shown on a shelf on the Career tab, and each one can be shared |

## 2. Direction

PEW's loop with the race replaced by a fight: **Build → Bench → Tune → Fight → Pit → Post-mortem → Build again.** The post-mortem is the part no other robot game does well; every loss must read as a design lesson.

What must feel great, in order:

1. **Hits.** A spinner connecting should feel like a car crash: sound, camera shake, haptic buzz, a part flying, a dent that stays.
2. **The post-mortem.** A clean report of every hit, what it broke, and why, with a redesign hint.
3. **The weight budget.** A bar that fills as you add parts; going over is impossible, so every gram is a choice.
4. **The pit window.** 60 seconds of real decisions between fights and between rounds.

**Setting flavour:** the Haldis is a precision-machining valley, not a steel town. You start in a rented corner of a watch-parts machine shop; club meets are at the Haldis Gemeindehalle, the valley's community hall. The Circuit act travels to the industrial towns: Stahlbrück's steel mills, Eisenau's river docks, Grauwald's rail yards. The Scrapline Open is televised from the Eisenhalle. Late-game CNC and titanium suppliers are Haldis machine shops.

**Palette (Longlight brand values):**

| Role | Dark | Light |
|---|---|---|
| Base / surface / card | `#141413` / `#1C1B19` / `#1F1E1B` | `#FAF9F5` / `#F1EEE7` / `#FFFFFF` |
| Accent (buttons, weight bar, active tab) | clay `#D97757` | clay `#D97757` fills; dark clay `#A8482A` for small text |
| Readouts (weapon J, rpm, timers) | lilac `#B48CE8` | ground purple `#6A33AD` |
| Border / muted text | — | `#E2DED5` / `#5F5C56` |
| Damage states | healthy green, worn amber, broken a **cool red** (around `#E5484D`) | same hues, darker shades for contrast |

Clay sits close to red, so damage never uses clay or an orange-red: a hurt bot must not look like the accent. Contrast-check every text colour on both themes (≥ 4.5:1).

Arena look: dark with hazard lighting and a crowd that's a cheap texture, not geometry. Workshop: cold light, steel and plywood, sparks.

## 4. PR 1: Parts, build maths, stress report (text only)

All in `src/sim/`. No DOM.

### 4a. Classes and the budget (`src/sim/parts.js`)

`CLASSES`: `{id, name, limitG, arenaId, partsTier, prizeScale, gridW, gridH}`. The weight limit is the whole design constraint. `build.totalG` must be `<= limitG` or the build is invalid. A build more than 5% under is a design flaw too (unused budget = armour you didn't fit); the stress report says so.

### 4b. Parts tables

`PARTS` is an object of slots; each option has `id`, `name`, `massG` (scaled per class via `classMult`), `cost` (euros, scaled by `prizeScale`), `unlock` (`start` | `tool:<id>` | `rnd:<id>`), and the stats below. First-pass values are guesses; tune in node.

| Slot | Options (first pass) | Stats |
|---|---|---|
| `chassis` | plywood box, HDPE box, aluminium box, steel box, titanium box, custom shape (R&D) | `massPerCell`, `hp`, `flex`, `cells`, `heightMm` |
| `armour` (per face: front, back, left, right, top) | none, HDPE 6/10/15 mm, aluminium, hardened steel, AR500, titanium | `massPerFace`, `absorb` (J before damage), `hp`, `deflect` (0..1 chance a glancing hit skids off) |
| `drive` | single motor per side, dual, brushless, high-torque gearbox | `massG`, `speed`, `torque`, `hp`, `cells`, `heatW` |
| `wheels` | foam, rubber, polyurethane, solid, tracks | `grip`, `hp`, `exposure`, `radiusMm` |
| `battery` | small LiPo, medium, large, high-discharge | `massG`, `capacityWs`, `dischargeW`, `hp`, `cells` |
| `electronics` | basic ESC, dual ESC, brushless ESC, failsafe, cooling | `massG`, `hp`, `maxPowerW`, `cells`, `heatW`, `coolingW` |
| `weapon` | none, wedge, lifter, flipper (pneumatic), hammer, horizontal spinner, vertical spinner, drum, undercutter, crusher (R&D), overhead saw (R&D) | `massG`, `motorMassG`, `cells`, `heatW`, `edgeMm` (leading edge height for wedges, lifters, undercutters), plus type-specific: `discMass`, `radius`, `rpmMax`, `spinUpS` (spinners); `shots`, `force` (flipper); `swingS`, `energy` (hammer); `reach` (wedge/lifter) |
| `weaponMaterial` | aluminium, steel, S7, titanium | `hp`, `massMult`, `bite` |
| `extras` | self-righter, skid plate, anti-spinner bar, minibot (R&D) | `massG`, effect |

### 4c. Layout grid

A chassis is a grid of cells (`gridW`×`gridH`, e.g. 4×6 for Beetle, 8×12 for Heavy). Drive pods, battery, ESC and weapon mount occupy cells. Each cell has an **exposure** value derived from distance to the nearest edge and the armour on that face. Parts in exposed cells die first. Centre-of-mass is computed from cell positions; a bot with the battery hanging off one side turns badly.

### 4d. Derived stats (`src/sim/build.js`)

`evalBuild(cfg)` returns (SI units):

- `massKg`, `underBudgetPct`, `com` (x,y offset in m), `moi` (yaw inertia), `polygon` (chassis outline for the sim).
- `driveSpeed = K.speed * torque / massKg` scaled by grip and class; `turnRate` from `moi` and wheelbase.
- **Height profile:** `clearanceMm` (from wheel radius and chassis), `frontEdgeMm` (lowest leading edge: the weapon's `edgeMm` if it has one, else the chassis front), `heightMm`, `invertible` (true if the bot drives the same either way up: symmetric height, wheels proud both sides, or a self-righter fitted).
- Spinner: `tipSpeed = rpm * radius`, `storedJ = 0.5 * I * omega^2` (I from discMass and radius), `spinUpS`, `recoilFactor`.
- Flipper: `shots`, `launchForce` vs opponent mass → does it actually flip them.
- `armourMapJ` per face, `weakestFace`, `exposureScore`.
- `runtimeS` from battery vs drive and weapon draw; a build that can't last 90 s is flagged.
- **Heat:** `heatRateW` (sum of `heatW`) vs `coolingW`; `secsToDerate` at full power. Above the limit, motors lose power in the fight and on the endurance test.
- `cost`, `buildHours`.
- **Stress report** from `COMBOS` (`src/sim/combos.js`): "spinner shaft will shear above 60 J on this material", "rear armour none: drive pods exposed", "spin-up 9 s: you lose the first exchange", "flipper can't lift a bot over 1.2 kg in this class", "battery runtime 70 s", "COM 30 mm off centre: pulls left", "front edge 6 mm: most wedges in this class get under you", "not invertible and no self-righter: one flip ends the fight", "drive overheats at 55 s".

### 4e. Node tests

`tools/sim-test.js`: evaluates `DEFAULT_CFG` and ~12 `TEST_BUILDS` (wedge, lifter, flipper, hsp, vsp, drum, hammer, undercutter, glass cannon, brick, invertible box, sloppy budget) per class and prints the derived stats. Also checks `src/sim/` for banned calls (section 0). Physics changes put before/after numbers in the commit message.

**Phone test:** none visual; Build tab shows the raw result object.

## 7. PR 4a: Fight simulation core (headless)

`src/sim/fight.js`, `src/sim/damage.js`, `src/sim/ai.js` (two basic drivers only), `src/app/debugview.js`. **Runs in node.**

### 7a. Simulation

- Fixed timestep 60 Hz, deterministic from a seed. **N bodies from the start:** `runFight({bots:[...], arena, seed, rules})`, where each bot has a team id. 1v1, rumble, tag team and minibots are just different bot lists and `rules`.
- Bots are 2D rigid bodies (convex polygon from `evalBuild`) with mass, yaw inertia, position, heading, velocity, angular velocity.
- **Input API:** every bot reads `{throttle, steer, weapon, selfRight}` per step (throttle and steer −1..1). The player's input comes from `app/controls.js`; AI input from `ai.js`. Nothing else drives a bot. The tactical control scheme (PR 5) converts taps into these same values.
- **Height axis (cheap pseudo-3D):** each bot also has `z`, `vz` and `inverted`. Flipper and lifter hits and floor-spinner hazards add `vz`; gravity brings it down. Airborne bots have no drive and skip bot-to-bot collisions. Landing damage scales with drop height (same maths as the drop test). A bot lands inverted if the launch was big enough; inverted and not `invertible` means it can't drive until it self-rights.
- **Wedge rules (`WEDGE_RULES`):** on front-to-front contact, the bot with the lower `frontEdgeMm` gets under the other if the gap beats a tolerance. The lifted bot loses grip and pushing force and its underside is exposed (hits on it bypass the front armour's `deflect`). Ties go to edge material and skid plates.
- Drive: wheel forces from throttle/steer, grip-limited, reduced per wheel lost. Heat accumulates per motor; past its limit, power derates.
- Weapon state: spinner rpm with spin-up and drag; flipper shots and recharge; hammer swing cycle.
- Collision: polygon overlap test, impulse resolution. A **hit** is logged when a weapon surface contacts an opponent face. Hit energy = spinner stored energy transferred by a `bite` factor (how much of the disc actually catches), or flipper/hammer energy. Spinner loses rpm on each hit; the attacker takes recoil impulse (`recoilFactor`).
- Round ends: knockout (a bot immobile for 10 s, including inverted and unable to self-right), pit (out of the arena), time up (judges' decision, section 8c).
- **Main-loop safety (app side):** the frame loop clamps the fixed-step accumulator to 5 steps per frame, and pauses the fight on `visibilitychange` so a stall or a pocketed phone never fast-forwards a round.

### 7b. Damage model (`damage.js`)

- A hit on a face: `absorb` eats energy; the rest damages the face armour `hp`; if the face is at 0, the energy passes to the most exposed cell behind it and damages that part.
- Part failures with effects: wheel lost (drive asymmetric), drive motor dead (one side out), ESC dead (that side out), battery hit (power loss, chance of smoke and knockout), weapon motor dead, weapon disc bent (energy halved, vibration), chassis flex (armour absorb reduced), self-righter dead.
- Self-damage: spinner hits above `weaponMaterial.hp` thresholds bend the disc; a hard hit at full rpm can shear the shaft.
- Every part ends the fight in one of three states: **intact**, **damaged** (hp left, repair fee) or **destroyed** (re-buy). The damage state is part of the fight result.
- Every hit and failure is appended to the **fight log** with time, attacker, face, energy, and outcome. This log is the post-mortem's input.

### 7c. Fight log and replay data

- The log holds: seed, both builds, arena, rules, the hit/failure entries, and **the player's inputs** (quantized to one byte per axis, run-length encoded). AI inputs are not stored; they regenerate from the seed. Seed + builds + player inputs = an exact replay.
- Cap: 20 KB per round including inputs. Cap hit entries and merge micro-hits to stay under it.

### 7d. Two basic AI drivers

`ai.js` ships two drivers now: **rush** (drive at the opponent, weapon on) and **keep-away** (circle, wait for spin-up, then close). Each has a skill 0..1 (reaction delay, aim error). The full style set is PR 4b.

### 7e. Debug view (`app/debugview.js`)

A plain 2D canvas, top-down: arena outline, bot polygons with heading lines, weapon arcs, hit flashes sized by energy, a lift/inverted marker. The Fight tab runs an AI-vs-AI fight of the current build and plays it here, with the text log underneath. This gives a visible, phone-testable fight two PRs before the 3D view, and it stays in the game as the replay thumbnail and an emergency Lite fallback.

### 7f. Node harness (first pass)

`tools/fight-test.js`: runs every `TEST_BUILDS` build against every other in its class, 20 seeds each, both AIs, and prints win rates, average damage, average fight length and knockout share. Times each step (target in section 16).

**Phone test:** the Fight tab plays a fight in the debug view; a wedge visibly gets under a high-fronted box; a flipper launches a bot and it lands inverted; tab away mid-fight and come back to find it paused.

## 8. PR 4b: AI styles, arenas, opponents, judges

`src/sim/ai.js`, `src/sim/arenas.js`, `src/sim/opponents.js`.

### 8a. AI drivers

`AI_STYLES`: aggressive, cautious, counter, box-rush, hazard-pusher, and (for rumbles) opportunist (attacks whoever is already damaged). An AI driver has a skill 0..1 and a style; it chooses from a small set of behaviours (close, circle, wait for spin-up, push to hazard, retreat to self-right, shove toward the pit). Deterministic from the seed.

### 8b. Arenas

`ARENAS`: walls, pit, pushers, a floor spinner. Each hazard has numbers in the table: impulse, damage J, `vz` kick, active time. Hazards are the whole offence of a weaponless wedge or pusher, so tune them in the harness like weapons. Each arena has a seed-stable layout. (The original "upper deck" idea is dropped: it can't work honestly in a 2D sim.)

### 8c. Judges

When time runs out, `JUDGE_WEIGHTS` decides (first pass: damage 0.5, aggression 0.25, control 0.25), each term defined from the fight log:

- **Damage:** total hp removed from the opponent's armour and parts.
- **Aggression:** share of the round spent closing or in contact, minus time spent retreating.
- **Control:** seconds the opponent spent lifted, pinned against a wall, inverted, or pushed into a hazard.

The post-mortem shows the three scores, so a judges' loss is still a lesson.

### 8d. Opponents

`OPPONENTS`: **start with ~15** named bots across classes (builds in the same config format as the player's, each with a driver, a style and a one-line personality). Grow toward ~40 later as content, not systems. The **meta** (`META_WAVES`, PR 8) shifts which archetypes appear each season.

### 8e. Balance harness and targets

`tools/fight-test.js` runs every build and opponent against every other in its class, 20 seeds each, AI driving both.

- **Archetype target:** no archetype above 65% or below 35% overall within a class.
- **Matchup spread is allowed:** individual matchups may sit as far apart as 20/80. The rock-paper-scissors (wedge beats horizontal spinner, vertical beats wedge, and so on) is the point; don't flatten it.
- **Lethality target:** single-hit knockouts happen in roughly 3–8% of fights in the heavier classes and less in Ant/Beetle; most knockouts come from a chain of two or more failures.
- Put the matrix in the commit message whenever physics or parts change.

**Phone test:** the Fight tab lets you pick an opponent and arena and watch it in the debug view; a hazard-pusher wins by the pit; a time-up fight shows the three judges' scores.

## 9. PR 5: Arena view, controls, hit feedback, sparring

`src/vis/`, `src/app/controls.js`, `src/app/fight.js`.

- **Parametric bots (`vis/bot.js`):** chassis from the polygon and grid, armour panels per face with thickness, wheels, weapon geometry by type (disc, drum, bar, flipper arm, hammer). Dents and missing parts come from the damage state. All code, all tiers; Blender hero shells (PR 10) are optional skins over this on Full/Ultra. Cache meshes by build hash and `dispose()` old geometry and materials whenever the build changes, so iterating in the workshop doesn't leak GPU memory.
- **Arena (`vis/arena.js`):** floor, walls (transparent on the camera side), hazards, cheap crowd texture, hazard lights. Lite: flat materials, no shadows.
- **Camera:** top-down tilted, follows the midpoint of the active bots, zooms with distance, shakes on hits scaled by energy (no shake under reduced motion).
- **Controls, two schemes (Settings → Controls):**
  - *Direct:* virtual stick left, weapon button right (swapped when Settings → left-handed). Self-right appears as a button when inverted.
  - *Tactical:* tap a point to drive there, tap the opponent to attack, tap your bot to back off. A small path-follower turns these into `{throttle, steer, weapon}`.
  - `ASSISTS` by driver skill apply to both schemes: auto-straighten, turn damping, weapon auto-spin when close.
  - **Multi-touch:** track each control by `pointerId` with `setPointerCapture`, so two thumbs never steal each other's input. `touch-action: none` on the arena only.
  - Keyboard WASD + space (+ R to self-right); gamepad if present.
- **Hit feedback (`vis/fx.js`):** sparks (particles, cheap), a part mesh flying off, dent decal, smoke on battery damage. **Haptics:** PEW's `buzz()` scaled by hit energy. Sound: synthesized clangs and motor whine from `sound/synth.js` scaled by hit energy; CC0 samples layered on Full/Ultra later (PR 10).
- HUD: round clock, every bot's damage silhouette (faces and internal parts lit green / amber / cool red), weapon rpm, battery, heat.
- **Sparring mode:** the Fight tab can pick any opponent in your class and any unlocked arena, no stakes, no damage bill. This is the Fight tab before the career exists and stays useful forever.
- Lite: 30 fps render cap, particles capped, no post. Full: shadows. Ultra: bloom on sparks.

**Phone test (Lite):** spar a beetle with each control scheme; land a spinner hit and feel the buzz and see a part fly; get flipped and self-right; play a rumble; fps steady, no auto-adjust toast.

## 10. PR 6: Pit window, post-mortem, replay

`src/app/pit.js`, `src/app/report.js`.

- **Pit window:** 60 real seconds, used **between rounds** in a best-of-three **and between fights on the same event day** (bracket rounds). That second use means the pit matters from the first tournament, not just finals.
- **Pit kits (`PIT_KITS`):** basic, full, pro, bought before each event, priced by class `prizeScale`. A kit lists which repairs it allows and how many: basic has wheels and bodges; full adds belts, armour panels and a battery; pro adds a drive pod and a spare weapon disc.
- **Repairs (`REPAIR_TIMES`):** wheel swap 15 s, belt 20 s, drive pod 35 s, battery 25 s, armour panel 30 s, bodge (half strength, 10 s). The clock keeps running while you decide. Pit crew staff (PR 8) cut these times. The clock pauses if the page is hidden.
- **Post-mortem (`app/report.js`):** a timeline of hits with energy, a damage map of your bot (intact / damaged / destroyed), the cause chain for each failure ("front-left wheel lost at 0:42: undercut at 85 J; front edge 6 mm, theirs 2 mm, so they got under you"), the judges' scores if it went to time, and a **redesign hint** generated from the same `COMBOS` rules.
- **The repair bill** sits at the bottom of the post-mortem: each damaged part's fee and each destroyed part's price, plus workshop hours, so the cost reads as a direct consequence of the hits.
- **Opponent's build is revealed** after the fight. **Copy to designs** saves it as a named blueprint in `DESIGNS` (you still pay to fit it). Studying and stealing a meta build is part of the game.
- **Replay:** re-runs the sim from the log (seed + builds + player inputs), so it works on **all tiers**, including in the debug view on Lite. Scrubbing needs keyframes (full sim state every 2 s) and is Full/Ultra only; Lite replays play straight through.

**Phone test:** lose a round, pit-repair under the clock with a basic kit, win the next, read the post-mortem and its repair bill, follow its hint, replay the fight.

## 11. PR 7: Career, circuit, money, saves

`src/app/career.js`, tables at the top of `src/app/state.js`.

- **Time model (`TIME`):** 52 weeks a season; act, then Close week. Each week gives workshop hours (`hoursPerWeek` grows with `WORKSHOP_STAGES` and staff). Building, repairs, the full bench suite and R&D spend hours. Events are pinned to weeks; travel takes days and money.
- **Acts:** Garage (Ant/Beetle, club meets at the Haldis Gemeindehalle), Circuit (Hobby/Feather, regional tournaments in Stahlbrück, Eisenau and Grauwald, brackets), Heavyweight (the Scrapline Open at the Eisenhalle, televised, team), Legacy (multi-bot team, kit line, mentoring).
- **Calendar (`SEASON_EVENTS`):** club meets, tournaments (single-elimination brackets, several fights in one day, pit windows between), rumbles, tag team, a championship. Entry fees, travel costs (further from the Haldis = dearer and longer), pit kit purchase before each event. Venue names from `WORLD`.
- **Money (euros):** prizes (`prizeScale` by class), sponsors later, kit sales later. Spending: fitting parts, repair bills, pit kits, tools, workshop, travel, entry fees. Going broke: the Haldis Savings Bank lends once; broke a second time ends the run with a restart offer.
- **Repair after a fight (`REPAIR_COST`, `REPAIR_HOURS`):** damaged parts cost a fee scaled by damage taken (first pass: 10% to 60% of the part's price, by hp lost); destroyed parts are re-bought at full price. A badly damaged bot may not be ready for the next event if you lack the hours.
- **Tools (`TOOLS`):** hand tools, 3D printer, bandsaw, drill press, welder, mill, lathe, CNC, press brake. Tools gate parts (`unlock: tool:<id>`) and cut build hours.
- **Workshop (`WORKSHOP_STAGES`):** a rented corner of a Haldis machine shop → own unit → shop → team HQ, with a trailer for travel.
- **Driver skill** levels with fights and drives the assist level; a hired driver (PR 8) has a fixed skill.
- **Rivals (`RIVALS`):** a few named builders with evolving bots who remember fights and trash-talk in one line.
- Save/Restore with `SCR1:` codes and backup files, three slots.

**Phone test:** play a Beetle season on Lite: a club meet, a tournament with two fights and a pit window between, pay a repair bill, buy a tool, travel, back up and restore.

## 12. PR 8: Research, team, sponsors, meta

- **R&D (`RND`):** custom chassis shapes, crusher, overhead saw, exotic armour, custom motor winding, pneumatics upgrade, minibots, your own weapon disc profile (name it). R&D costs hours and euros.
- **Team (`STAFF`):** engineer (cuts build hours, better stress reports), fabricator (unlocks custom parts), driver (fixed skill), pit crew (faster pit repairs). Salaries per season.
- **Sponsors (`SPONSORS`):** offers after placings. Each wants its colour on the bot (a paint slot) and sets a **placing target** for the season; pay per season, and they drop you if you miss it.
- **Meta evolution (`META_WAVES`):** the opponent field shifts per season (spinner era → wedge era → undercutter era → armour era). **Rule changes (`RULES_BY_SEASON`):** a weapon energy cap, a new hazard, a class limit tweak, announced a season ahead.
- **Kit line:** late game, publish one of your designs as a kit; income per season scaled by its win rate in the sim.

## 16. Performance budget (all PRs)

- Fight sim: ≤ 2 ms per 60 Hz step on a phone for a 1v1, ≤ 4 ms for a 4-bot rumble (profile in node and the browser).
- Lite render: one scene, ≤ 40k triangles in the arena, ≤ 200 particles, 30 fps cap, no shadows or post.
- Fight log ≤ 20 KB per round including recorded inputs.
- No `backdrop-filter` stacking beyond PEW's budget; custom-property writes throttled.
- Bot meshes cached and disposed (section 9); no GPU memory growth after 20 build changes.
- After each PR, on a phone: the "Graphics lowered" toast must not appear where it didn't before.
